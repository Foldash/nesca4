# Аудит и состояние рефакторинга

Обновлено 21 ноября 2026 года. NESCA 4 включает первые исправления ошибок памяти и новый интерфейс Qt Widgets. Полная стабилизация старого ядра ещё не завершена.

## Исправлено

| Файл | Изменение |
| --- | --- |
| `src/Utils.h` | Локаль в компараторе хранится по значению вместо ссылки на уничтоженный параметр конструктора. |
| `src/Utils.h` | Разбор описания ошибки проверяет null, конец строки и отсутствующие кавычки; QString создаётся с явной длиной вместо чтения массива без завершающего NUL. Предел значения 128 байт сохранён. |
| `src/nesca_3.cpp` | Исправлена пара new/delete для объекта Ui. |
| `src/MainStarter.cpp`, `src/finder.cpp` | Исправлены две пары new[]/delete. |
| `src/BoundedResponse.h`, `src/Connector.cpp` | Размер блока проверяется до добавления, исключены переполнение умножения и выход исключений через C callback. Лимит ответа — 180000 байт. |
| `src/Connector.cpp` | Добавлено освобождение curl_slist и обработка отказа append без потери предыдущего списка. |

На исходном Utils.h санитайзер воспроизвёл stack-use-after-scope, stack-buffer-overflow, global-buffer-overflow и SEGV при отсутствии кавычек. На исправленной версии семь групп регрессионных проверок проходят обычную сборку и ASan/UBSan. Граничные тесты буфера тоже проходят ASan/UBSan. Проверка санитайзерами проводилась до переноса неизменённых функций в NESCA 4; после переноса тесты повторно прошли через CTest.

LeakSanitizer в среде аудита недоступен из-за ptrace; ASan/UBSan запускались с detect_leaks=0. Отсутствие всех утечек не подтверждено. Освобождение curl_slist и исправления интеграции полного приложения требуют отдельной динамической проверки.

Разбор описания ошибки пока сохраняет старый формат и не является полноценным JSON-парсером. Экранированные кавычки и границы UTF-8 при ограничении длины требуют отдельной правки.

## Изменения интерфейса

Новая `nesca_3.ui` использует layouts вместо абсолютного размещения. Имена всех существующих виджетов сохранены, чтобы старые обработчики могли обращаться к новой форме. Журнал и таблица авторизации размещены на отдельных вкладках; переключение больше не очищает модель. Задания открываются вкладкой вместо перемещения панели за край окна.

Сводка обновляет текстовые значения без рисования скрытых круговых индикаторов и деления на нулевые счётчики. Старые циклы графических анимаций и удалённые проверки версии/почтового сервера исключены из автозапуска. Остальные нарушения потоковой модели ядра этим не устранены.

`nesca4-ui` собирается независимо от ядра и не выполняет сетевых действий. Тест UI прошёл для трёх размеров окна, четырёх вкладок параметров и трёх вкладок результатов. Снимок `interface.png` получен с настоящих Qt-виджетов этой сборки. Полная инженерная сборка на Linux теперь проходит; проверены открытие/закрытие окна, обработка неверного ввода и повторный запуск. Сетевые сценарии и полное ядро Windows не проверены.

21 ноября опубликован Windows x64 ZIP предпросмотра с Qt 5.15.2 и DLL MSVC. На Windows Server 2022 прошли CTest 3/3 и обычный запуск распакованной копии без установленного Qt в PATH. Сборка GUI использует Windows subsystem без отдельного консольного окна. В тесте буфера проверки больше не зависят от assert и выполняются также в Release. [Проверенная сборка](https://github.com/Foldash/nesca4/releases/tag/ui-preview-3).

## Управление сеансом

21 ноября добавлен ThreadPool, который не зависит от Qt и сетевых библиотек. Очередь ограничена, блокирующие производители пробуждаются при отмене; завершение учитывает и очередь, и выполняемые задания. Старт и join сериализованы, повторный запуск очищает счётчики и ошибки. Исключение в задании сохраняется как ошибка задания; worker продолжает работу. Блокирующие операции над собственным пулом из worker отвергаются вместо взаимной блокировки.

Адаптер Threader запускается явно владельцем сеанса. MainStarter дожидается его завершения перед очисткой списков и libcurl. Счётчик соединений возвращается в исходное состояние через RAII также при исключении. Флаг отмены globalScanFlag стал atomic. QThread::terminate и join из обработчиков GUI исключены из пути завершения. Повторный запуск и закрытие окна учитывают QThread::finished.

Фоновые detached-потоки загрузки списков, таймера и сохранения убраны из пути сеанса. Списки фиксируются от загрузки до join; ожидание их готовности использует собственный local unique_lock читателя. Несовместимый тип указателей на функции загрузчика заменён точным void (*)(). Периодическое сохранение при работающем производителе временно отключено; финальное сохранение выполняется после остановки. Внешняя старая база отключена, поэтому завершение не ждёт неработающего отправителя JSON.

Устранены ошибки компиляции без permissive: преобразование указателя в длину буфера, сужение байтовых констант, несогласованные объявления atomic и копирование atomic в variadic-вызов. Добавлены отсутствовавшие возвраты статусов. Старый массив callback-мьютексов OpenSSL удалён; используется автоматическая инициализация OpenSSL 1.1.1+ ([документация OpenSSL](https://docs.openssl.org/3.5/man3/OPENSSL_init_crypto/)).

Локальная полная сборка: GCC15.2, Qt5.15.18, libcurl8.18, libssh0.11.3, OpenSSL3.5.5. CTest7/7: UI preview, Utils, BoundedResponse, открытие/закрытие полного окна, два ошибочных сеанса подряд, пул и адаптер Threader. Тесты ошибочного ввода используют отдельную папку сборки и завершаются до сетевых действий. Пул и адаптер прошли ThreadSanitizer; пул также прошёл ASan/UBSan с detect_leaks=0. Это не проверка всего сетевого ядра санитайзерами. Искусственный отказ создания потока не инъецировался; отмена уже выполняющегося сетевого запроса не измерялась.

В GitHub Actions подтверждены полная Linux-сборка GCC13.3 и CTest7/7, а также Windows preview/runtime MSVC19.44 и CTest5/5. Проверка распакованного Windows-пакета успешна. Полное сетевое приложение Windows этими проверками не собирается.

## Открытые задачи

1. **Сетевые тайм-ауты и отмена ввода-вывода.** Новый пул корректно учитывает задания, но выполняемый сетевой запрос останавливается кооперативно и по тайм-ауту библиотеки. Нужны локальные серверные заглушки и проверки закрытия во время чтения/записи.
2. **Списки и импорт.** Перезагрузка char** при работающих читателях отключена. Остаются ручное владение, двухпроходная загрузка и ошибки обработки длинных/неверных строк, отказов выделения памяти и совпадающих размеров файлов. Нужны контейнеры RAII и неизменяемые снимки с проверенной публикацией.
3. **Общие данные и GUI.** globalScanFlag теперь atomic; остаются Activity, общие строки/счётчики и прямое изменение GUI-модели из worker. Для них требуются отдельные снимки состояния, сигналы в GUI-поток и тесты TSan. Исправление пула не устраняет все гонки приложения.
4. **Парсеры и копирование.** В finder остаются вычитание nullptr и копирование недоверенных длин в фиксированные массивы. Поля GUI тоже передаются в C-массивы. Нужны чистые парсеры с проверками границ и фаззингом.
5. **Данные авторизации.** Проверка сертификатов отключена в старом Connector; перенаправления могут расширять передачу авторизации. В журналах и старой сериализации встречаются открытые учётные данные. Нужны проверка TLS, маскирование секретов и явные правила хранения.
6. **Полное ядро Windows.** Переносимая Windows-сборка проверена для UI preview. Всё ядро пока собрано только на Linux; ресурсы, SDK и зависимости Windows требуют отдельной миграции. Исторические qmake-файлы не являются поддерживаемым способом сборки.

Производительность и максимальное потребление памяти всего приложения не измерены. Готовность к стабильному выпуску следует оценивать после проверки реальных сетевых операций на локальных заглушках, отмены, повторного запуска, закрытия окна и отсутствия фоновой работы после завершения сеанса.
